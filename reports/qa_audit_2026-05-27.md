# LexAI QA Audit - 2026-05-27

## Scope

Audit nhanh cho FastAPI backend va React/Vite frontend, tap trung vao:

- Error handling va fallback khi MongoDB/vector search khong san sang.
- Context retention giua cac module phan tich phap ly.
- Nut bam/interactive element co hanh dong ro rang.
- TypeScript compile, backend tests, frontend build, route smoke.

## Changes implemented

### Backend resilience

- Them demo fallback cho `/retrieval/laws`, `/retrieval/similar-cases`, `/retrieval/clauses`.
- Them demo fallback cho cac endpoint recommendation can MongoDB: `/recommendations/documents`, `/recommendations/templates`, `/recommendations/risks`, `/recommendations/checklists`, `/recommendations/cases`.
- Khi `vector_storage` khong co hoac app chay `use_mongodb=False`, endpoint van tra ket qua co y nghia voi `search_mode=demo_fallback`.
- Bao quanh keyword fallback bang `try/except` de tranh loi MongoDB day len HTTP 500.
- `VectorStorage.log_interaction` khong lam hong request khi MongoDB interaction insert loi.
- Escape regex trong `keyword_search_cases` de tranh pattern loi khi user nhap ky tu dac biet.
- Startup Mongo index setup mac dinh duoc skip, co the bat bang `LEXAI_SETUP_MONGO_INDEXES=1`; tranh spam loi Atlas free-tier FTS index limit.

### Frontend UX and context retention

- Them `sessionStorage` shared situation context trong `frontend/src/lib/analysisContext.ts`.
- Cac module phap ly chinh dung chung context: Analyze, Actions, Journey, Timeline, EvidenceGap, LawSearch, SimilarCases, Risks.
- Khi user sua tinh huong o mot module, cac module tiep theo se prefill tu context gan nhat.
- `/similar-cases` bay gio tu hydrate va tu chay tim kiem khi user vao truc tiep tu URL nhung da co legal situation hop le trong shared context.
- `/similar-cases` chan truy van qua ngan truoc khi goi backend de tranh loi `422` va tranh ket qua nham khi user nhap ky tu ngau nhien.
- `/similar-cases` hien thi ro che do tim kiem `vector`, `keyword`, hoac `demo_fallback` trong thanh metadata ket qua.
- Localhost `:3000` dang serve thu muc phu `lexai-–-trợ-lý-pháp-lý-thông-minh UI`, nen da dong bo cung fix `SimilarCases.tsx` sang thu muc nay de test local phan anh dung code moi.
- Dashboard quick classify luu tinh huong vao shared context truoc khi phan loai.
- Mot so nut trang tri duoc gan hanh dong that:
  - Header notification button co feedback.
  - Dashboard recommendation cards/nut chi tiet dieu huong.
  - Documents grid/list toggle co state that.
  - Profile edit scroll den role section; "Kham pha ngay" dieu huong sang law search.
- API fetch now throws friendly connection errors when backend is unreachable.

### Dashboard real metrics pass

- Fixed frontend digest transformer to read backend `profile_summary` from `/recommendations/behavior/digest`.
- Removed the hard-coded `92%` matching rate on Dashboard.
- Dashboard overview now derives metrics from real backend behavior data plus local `lexai_sessions` and `lexai_analysis_history` fallback:
  - real interactions,
  - active days,
  - primary legal domain,
  - profile coverage,
  - conversation session count,
  - saved analysis count,
  - average recommendation score.
- Dashboard now shows a data-source note so demo users can see whether numbers are coming from backend behavior history or local browser history.
- Recommendation ranking cards now navigate with legal-domain context instead of a generic profile-only click.

## Current QA assessment

MVP demo is stable for the legal-analysis flow:

- Analyze -> recommendation -> evidence/action/timeline/journey/risk/law/similar-case modules now share context.
- Recommendation engine output and fallback search are usable even without a healthy vector index.
- The app builds and core backend tests pass locally.

Not yet production-complete:

- Full browser E2E interaction tests are still needed for form flows and modals.
- Some older text in the UI/source still contains mojibake and should be normalized in a separate copy/encoding pass.
- MongoDB Atlas vector indexes should be provisioned deliberately outside app startup for production.
- Auth, rate limiting, observability, and live Vercel env validation still need a production hardening pass.
